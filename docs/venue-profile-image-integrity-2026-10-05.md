# Venue profile image integrity — October 5, 2026

Reviewed the uncommitted parser patch prepared in the separate “Fix lightbox venue header and width” task. Its deletion prevention and confirmed-404 recovery logic were incorporated into the Luna parser branch as commit `582a127`. The current branch's other parser changes were preserved. One flaw in the draft was corrected: when a venue had no profile image, an incoming managed image that failed validation could still be returned as the event icon. The merged version returns it only after a successful image probe.

The parser now distinguishes an existing managed venue profile URL from an image created by this parse. Only the latter is eligible for temporary image cleanup. For a first-party venue post, an incoming managed profile image must return HTTP 200 with nonempty image content before it can replace a canonical venue image. An existing image is treated as missing only on HTTP 404; timeouts and other responses are not proof of deletion.
