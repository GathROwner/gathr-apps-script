## Museum class follow-up, October 2

The original dry run exposed two related defects: the three-hour duplicate tolerance matched both classes to Group 2, and the existing Group 1 and Group 2 records had wrong stored times even though their `timeFlags` contained the correct printed ranges. A general duplicate guard now recognizes explicit Group/Slot ordinals. When Luna omits the ordinal, it can match a labeled older group only when both sides carry explicit source time evidence, the title core agrees, and the printed start/end clocks agree. Distinct printed ranges are not treated as the same group. The merge evidence parser now ignores `Group 1 -` as a label rather than mistaking `1` for a clock.

The first production retest on selected-row revision `processdatasetselectedrows-00376-2cz` found both times but dropped the slot labels from both titles. It still predicted both would map to Group 2, so it was a failed gate. The second retest on revision `processdatasetselectedrows-00378-7zp`, task `luna-museum-artclub-dry-20261002-04`, completed run `1a7c525a-0dcc-4bd0-bfda-f5de80cdf603`, snapshot `1OmFzDG0kWiY-k8C-8G6-oGlTBxE3B0cq_144_1790968448987`. It extracted two separate eight-Sunday series, 12:30–13:45 and 14:15–15:30, with the four original gallery images. The [read-only payload and merge preview](../artifacts/luna-live-canary-2026-10-02/museum-preview-production-evidence-fix-dry.json) maps the first to existing Group 1 document `3DO8t0Eyl1TB8scIBfEx` and the second to Group 2 `nOz8TgJISaSmdkMUVNzY`; it predicts correction of both start/end pairs.
